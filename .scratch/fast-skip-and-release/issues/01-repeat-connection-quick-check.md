# 01: 重复接入时快速跳过已导入素材

**What to build:** 相机再次接入时，已经导入完成、且来源和归档都没有变化的文件，不再重新读取整张卡和整个归档做 SHA-256，而是凭清单记录快速判定为“已有”。用户仍可以手动发起一次“完整核对”，重新读取全部素材。新复制的文件，校验时读的是磁盘上的数据，而不是刚写入的系统缓存。

**Blocked by:** None (can start immediately)

**Status:** resolved

背景：现在只要清单里有记录或目标已存在，就会对来源和目标各算一遍哈希。卡上有 100GB 旧素材时，每次接入都要读约 200GB，自动导入因此显得很慢。

- [x] 清单记录来源修改时间、目标修改时间与目标文件身份；来源路径、大小、修改时间都一致，且归档文件仍是同一个未改动的普通文件时，跳过且不读取内容
- [x] 任何一项不一致（包括旧版清单缺少新字段）时，回到现有的完整核对路径；损坏归档仍会被发现并另存新副本，不覆盖
- [x] 提供“完整核对”入口（菜单栏右键与命令行），强制对所有文件走完整核对
- [x] 复制后的读回校验绕过页缓存
- [x] fixture 检查覆盖：快速跳过不读取来源内容、来源变化、归档被改写、旧版清单、完整核对模式
- [x] 原有 10 项与重构带来的 2 项检查全部通过

不做：清单批量写入。逐文件写清单是 GLOSSARY 中“导入完成 = 已记录完成状态”的一部分，几百个文件的 JSON 开销可以忽略。

## Comments

2026-10-11 实现（分支 `feat/fast-skip-and-release`）：
- 清单记录新增 `sourceModified` 和归档文件身份（inode、大小、纳秒级 mtime）。旧版清单缺少这些字段，会先完整核对一次，再升级成快速记录。不记录设备号，因为外接磁盘重新挂载后设备号会变。
- 菜单栏右键新增“完整核对已导入素材”，命令行新增 `--full-verify`。
- 复制和哈希读取都设置 `F_NOCACHE`，写完后执行 `F_FULLFSYNC`。这是尽力而为：`F_NOCACHE` 不保证清掉同一文件已经缓存的页。这一点已在 review 中说明并接受。
- 已知边界：同大小的原地改写，如果 inode 和纳秒 mtime 都被还原，快速模式识别不出来；这种情况要用完整核对。

验证：
- `swift run ActionImportChecks` 17/17 PASS，在 Asia/Shanghai、America/Los_Angeles、Pacific/Kiritimati 三个时区分别运行。
- CLI 用 2GB 随机文件测试：首次导入 2.62s，快速重复 0.01s，`--full-verify` 1.82s。
- 双轴 code review 已完成。已修复：缺少“归档被改写”检查、记录按来源索引、去掉设备号、合并重复的进度发送、修正注释。拒绝的意见：`ImportPresentation` 与 `ImportProgress` 两套 Phase 合并（属于既有重构的取舍，超出本票范围）、`DateFormatter` 缓存的复杂度（仍然保留）。

未验证（需要维护者处理）：真机 Action 6 重复接入，以及 App 内右键“完整核对”的手动点击测试。
