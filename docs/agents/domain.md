# Domain Docs

This is a single-context project.

Before exploring, read `GLOSSARY.md` at the project root and relevant documents under `docs/adr/`, when present. If absent, proceed silently. Domain-modeling creates them lazily when terms or decisions are resolved.

Use the glossary's canonical vocabulary in tickets, tests and explanations. Resolve overloaded or conflicting terms instead of silently substituting synonyms.

Create ADRs only for decisions that are hard to reverse, surprising without context and the result of a real trade-off. Flag conflicts with existing ADRs explicitly.
